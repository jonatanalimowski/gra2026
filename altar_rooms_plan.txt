ALTAR ROOMS - ARCHITECTURE PLAN
===============================

Goal
----
A reward room at the end of a side branch with an altar. Interacting with it shows 3 "pacts".
Each pact = a run-wide BUFF + a run-wide CURSE. You take one, or walk away with nothing.

Examples:
  - "Defeated monsters have a 25% chance to explode, damaging you AND other monsters"
    (buff and curse are the same mechanic here: free AoE vs. danger to yourself)
  - "Your spells have a 15% chance to be vampiric, healing you for 3 HP on hit,
     BUT your max health is halved"

What already exists and can be reused
-------------------------------------
  - StatModifier + StatBlock.AddModifier(mod, source)  -> "max health halved" is just
    StatModifier { stat = max_health, multiplier = 0.5 }. Health.SetMaximum keeps the hp ratio.
  - Effect (projectile hooks)  -> "vampiric spells" is an Effect (roll in OnProjectileSpawned,
    heal in OnHitTarget).
  - RunState.player_modifiers / RunState.effects  -> already meant for this ("blessings, altars"),
    already cleared by RunState.Begin(), already applied in Player.ApplyLoadout().
  - ItemData + ChoiceCard  -> a pact can extend ItemData, so ChoiceCard can show it.
  - RoomData.RoomType.SHRINE + DungeonGenerator putting non-COMBAT rooms at branch ends
    -> the altar room just needs a scene + RoomData with room_type = SHRINE.
  - RestRoom  -> template for a non-combat room with an interactable (Area2D + one-time use).
  - Signals.enemy_killed(enemy)  -> hook point for "on kill" curses/buffs.

What's MISSING (the actual work), in order
------------------------------------------
  1. A pact data type (AltarPact) that bundles buff + curse.
  2. A second kind of effect for things that are NOT projectile hooks (on kill, on player hit,
     on room cleared...). Effect only runs inside projectiles right now.
  3. A dispatcher that calls those run-wide hooks when the matching global signal fires.
  4. Applying a pact LIVE (mid-floor). Right now RunState stuff is only applied in Player._ready.
  5. Kill info: who/what killed an enemy (needed so explosions don't chain forever, and for
     future "on kill with spell X" effects).
  6. A reusable explosion / AoE damage scene that hits both teams.
  7. Enemy-side modifiers (for curses like "enemies have +30% HP") - optional but cheap to add now.
  8. The choice overlay UI (3 cards + Leave). Build it generic -> reuse for post-room blessings.
  9. The AltarRoom scene/script + RoomData + seeded offer pool.
 10. HUD list of active pacts, debug commands.

Each step below.


===========================================================================================
1. AltarPact (data)                         Scripts/Resources/Items/AltarPact.gd
===========================================================================================
Extends ItemData so ChoiceCard and later the Hub/codex can show it with no changes.
A pact is just lists of "things to add to the run". Buff and curse are both lists, kept apart
only so the card can color them differently (green / red).

    extends ItemData
    class_name AltarPact

    # buff half
    @export var buff_text: String = ""
    @export var player_modifiers: Array[StatModifier] = []
    @export var effects: Array[Effect] = []           # projectile hooks (vampiric, etc.)
    @export var run_effects: Array[RunEffect] = []    # event hooks (explode on kill, etc.)

    # curse half
    @export var curse_text: String = ""
    @export var curse_player_modifiers: Array[StatModifier] = []
    @export var curse_effects: Array[Effect] = []
    @export var curse_run_effects: Array[RunEffect] = []
    @export var enemy_modifiers: Array[StatModifier] = []   # see step 7

    # offer pool settings
    @export var weight: float = 1.0
    @export var min_floor: int = 1

Notes:
  - A pact where buff and curse are the same mechanic (exploding monsters) just puts one
    RunEffect in run_effects and leaves curse lists empty. The texts still split it up for the card.
  - Description text: put numbers in the text by hand at first ("25%"). Later, if you tune a lot,
    give ItemData a virtual GetDescription() that pacts override to read numbers from their
    effects, so text never goes out of sync.
  - Data lives in Data/Altars/*.tres, one per pact (same as Data/Wands, Data/Runes).
  - Same rule as everywhere: never edit these .tres at runtime. Numbers inside Effects are
    read-only config; per-run state goes elsewhere (see step 2).


===========================================================================================
2. RunEffect (event hooks)                  Scripts/Combat/Effects/RunEffect.gd
===========================================================================================
Effect = "how a projectile behaves". Exploding corpses have nothing to do with projectiles,
so don't cram it into Effect. Make a sibling base class with world-level hooks. Override
only what you need, same style as Effect:

    extends Resource
    class_name RunEffect

    # Run-wide behaviour that reacts to game events instead of projectiles
    # (altars, blessings, later relics). Called by RunState, see RunState.Dispatch*.
    # Shared resource: keep per-run state in RunState.run_effect_state[self], not in variables.

    func OnAdded(_player: Player) -> void: pass           # picked up / player spawned on new floor
    func OnEnemyKilled(_enemy: Entity, _info: DamageInfo) -> void: pass
    func OnPlayerDamaged(_player: Player, _info: DamageInfo) -> void: pass
    func OnRoomEntered(_room: Room) -> void: pass
    func OnRoomCleared() -> void: pass
    func OnFloorStarted() -> void: pass

Add hooks only when a pact actually needs them. The first two pacts need OnEnemyKilled only.

Example - ExplodeOnKillEffect.gd:

    extends RunEffect
    class_name ExplodeOnKillEffect

    @export_range(0.0, 1.0) var chance: float = 0.25
    @export var damage: float = 15.0
    @export var radius: float = 48.0
    @export var explosion_scene: PackedScene

    func OnEnemyKilled(enemy: Entity, info: DamageInfo) -> void:
        # an explosion kill can't explode again, otherwise one kill clears the room
        if info and info.element == &"explosion":
            return
        if randf() > chance:
            return
        var explosion = explosion_scene.instantiate()
        explosion.Setup(damage, radius, enemy)
        explosion.global_position = enemy.global_position
        # Die() runs inside a physics callback, adding areas there is not allowed
        enemy.get_tree().current_scene.add_child.call_deferred(explosion)

(Decide later whether chains are fun - you can allow them with a max depth instead of a hard no.)

Example - VampiricSpellEffect.gd (this one IS a normal projectile Effect):

    extends Effect
    class_name VampiricSpellEffect

    @export_range(0.0, 1.0) var chance: float = 0.15
    @export var heal_amount: float = 3.0
    @export var tint: Color = Color(1, 0.3, 0.3)

    func OnProjectileSpawned(projectile: BaseProjectile) -> void:
        var is_vampiric = randf() < chance
        projectile.effect_state[self] = is_vampiric
        if is_vampiric:
            projectile.sprite.modulate = tint      # player must SEE which shots are vampiric

    func OnHitTarget(projectile: BaseProjectile, _target: Node2D, _info: DamageInfo) -> bool:
        if projectile.effect_state.get(self, false) and projectile.caster is Player:
            projectile.caster.health.Heal(heal_amount)
        return false

  Gotcha: OnProjectileSpawned runs in _ready, after @onready, so projectile.sprite exists. OK.
  Gotcha: Pierce/Bounce return true to survive -> a vampiric piercing shot heals per enemy hit.
          That's probably fine (synergy!), just know it.

3. Dispatching run effects                  Scripts/Global/run_state.gd
===========================================================================================
RunState already owns the run-wide lists and lives for the whole run, so it's the natural
place to forward global signals to RunEffects. No new autoload needed.

    var pacts: Array[AltarPact] = []                 # what was taken (for HUD, no duplicates)
    var run_effects: Array[RunEffect] = []
    var enemy_modifiers: Array[StatModifier] = []
    var run_effect_state: Dictionary = {}            # per-run data for RunEffects, key = effect

    signal pact_added(pact: AltarPact)               # or put it in Signals, your call

    func _ready() -> void:
        Signals.enemy_killed.connect(_on_enemy_killed)
        Signals.player_damaged.connect(_on_player_damaged)
        Signals.room_cleared.connect(func(): for e in run_effects: e.OnRoomCleared())

    func _on_enemy_killed(enemy: Entity, info: DamageInfo) -> void:
        if not is_run_active:
            return
        for e in run_effects:
            e.OnEnemyKilled(enemy, info)

    func AddPact(pact: AltarPact) -> void:
        pacts.append(pact)
        player_modifiers.append_array(pact.player_modifiers)
        player_modifiers.append_array(pact.curse_player_modifiers)
        effects.append_array(pact.effects)
        effects.append_array(pact.curse_effects)
        run_effects.append_array(pact.run_effects)
        run_effects.append_array(pact.curse_run_effects)
        enemy_modifiers.append_array(pact.enemy_modifiers)
        pact_added.emit(pact)

    Begin(): also clear pacts, run_effects, enemy_modifiers, run_effect_state.

Why keep the flattened lists AND pacts: Player/Entity only care about "all modifiers/effects",
the HUD and the offer pool care about "which pacts". Later blessings can call the same
"add these lists" code - consider a shared base (e.g. pact and blessing both extend a
"RunBoon" resource) once blessings exist. Don't build that abstraction before then.


===========================================================================================
4. Applying a pact live                     Scripts/Entities/Player.gd
===========================================================================================
Player.ApplyLoadout already applies RunState lists on _ready (= start of every floor, and
Ctrl+R, since RunState.Begin clears them). What's missing is the mid-floor case: you pick a
pact and it must work immediately.

    func _ready():
        ...
        RunState.pact_added.connect(ApplyPact)

    func ApplyPact(pact: AltarPact) -> void:
        for modifier in pact.player_modifiers + pact.curse_player_modifiers:
            stats.AddModifier(modifier, RunState)
        effects.append_array(pact.effects)
        effects.append_array(pact.curse_effects)
        for e in pact.run_effects + pact.curse_run_effects:
            e.OnAdded(self)

  - max_health x0.5: AddModifier emits stat_changed -> _on_stat_changed -> health.SetMaximum,
    which keeps the % -> 80/100 becomes 40/50 and the HUD updates through player_health_changed.
    Decide if that's what you want (alternative: keep current hp, clamp to new max).
  - Source = RunState for everything run-wide, consistent with ApplyLoadout. If you ever want
    to REMOVE a single pact (cleansing shrine?), use the pact itself as the source instead.
  - Player.effects is passed by reference into each cast (SpellCaster.TryCast copies it into a
    new array per cast), so new effects affect the next shot, not ones already flying. Good.
  - Careful not to double-apply: ApplyPact must only run for NEW pacts, ApplyLoadout handles
    the ones from earlier floors. Since the signal only fires in AddPact, that's automatic.

5. Kill info + player damage signal
===========================================================================================
"Defeated monsters explode" needs to know HOW the monster died (explosion? which spell?).

  EntityBase.gd:
    var last_hit: DamageInfo
    TakeDamage(info): last_hit = info  (before health.Damage, because Damage may call Die)
    Die(): Signals.enemy_killed.emit(self, last_hit)

  signals.gd:
    signal enemy_killed(enemy: Entity, info: DamageInfo)   # add the param (update listeners)
    signal player_damaged(info: DamageInfo)                # new, emitted in Player.TakeDamage
                                                           # after the invulnerable check

  DamageInfo: use element = &"explosion" for now. If you start tagging more stuff
  (thorns, burn ticks, "from pact"), switch to `var tags: Array[StringName]` so a hit can be
  both "fire" and "explosion".

  Note: Die() calls queue_free right away. Effects reacting to the kill must copy what they need
  (position!) during the call - don't keep a reference to the enemy for later.

6. Explosion / AoE damage                   Scenes/Combat/Explosion.tscn + Scripts/Combat/Explosion.gd
===========================================================================================
You'll need AoE for a lot more than this pact (bombs, fireball impact, boss slams), so make it
a standalone scene.

  Node: Area2D (root, script) + CollisionShape2D (CircleShape2D) + AnimatedSprite2D (VFX from
  assets/new_assets VFX pack).
  Mask: LAYER_PLAYER | LAYER_ENEMY (constants in Projectile.gd - consider moving the layer
  constants to a small shared script, you'll need them in more places now).

    extends Area2D
    class_name Explosion

    var damage: float
    var source: Node2D
    @export var knockback_force: float = 250.0
    @export var hits_player: bool = true
    @export var hits_enemies: bool = true

    func Setup(dmg: float, radius: float, damage_source: Node2D) -> void: ...

    func _ready():
        # overlaps are only known after one physics frame
        await get_tree().physics_frame
        await get_tree().physics_frame
        for body in get_overlapping_bodies():
            if not body.has_method("TakeDamage"): continue
            if body is Player and not hits_player: continue
            if body is Entity and not hits_enemies: continue
            var info = DamageInfo.new(damage, source)
            info.element = &"explosion"
            info.knockback = (body.global_position - global_position).normalized() * knockback_force
            body.TakeDamage(info)
        $AnimatedSprite2D.play("explode")
        await $AnimatedSprite2D.animation_finished
        queue_free()

  Alternative to the await: PhysicsShapeQueryParameters2D + intersect_shape for an instant query.
  Either is fine; the await version is easier to read.

  Readability: an exploding corpse that hurts the player must be telegraphed or it feels
  unfair. Do a short delay (0.3-0.5 s) with a flashing circle on the floor before the damage.
  Easy to add here: tween a circle sprite, then do the damage loop.

  Free interactions you get: dash invulnerability dodges explosions (Player.TakeDamage already
  checks is_invulnerable), knockback works through the existing DamageInfo.knockback, bosses
  with knockback_resistance 1 aren't pushed.

7. Enemy-side modifiers (optional, cheap now)
===========================================================================================
Curses like "enemies have +30% HP / +20% speed" need enemies to read RunState too.
In EntityBase._ready, after FromResource and BEFORE creating Health:

    for modifier in RunState.enemy_modifiers:
        stats.AddModifier(modifier, RunState)

Enemies spawn when a room is entered, so new curses affect the next room automatically.
If you later want "elite" curses (some enemies get a buff), that's a RunEffect hooking a new
"OnEnemySpawned(enemy)" call from EnemyRoom.SpawnEnemies.

  and that Esc/close also unpauses. Also block player input while open (paused tree does that
  for _unhandled_input since the player is PAUSABLE).

9. AltarRoom + offer pool                   Scripts/Worldgen/AltarRoom.gd, Scenes/World/RoomScenes/AltarRoom.tscn
===========================================================================================
Copy the structure of RestRoom:

    extends Room
    class_name AltarRoom

    @export var pact_pool: Array[AltarPact]      # drag in Data/Altars/*.tres
    @export var offer_count: int = 3
    @onready var altar: Area2D = $Altar
    var offers: Array[AltarPact] = []
    var is_used: bool = false
    var player_in_range: bool = false

    _ready: roll offers (see below), connect altar body_entered/exited -> player_in_range,
            show an "E" prompt label when in range.
    _unhandled_input: if player_in_range and not is_used and "Interact" pressed -> open overlay.
    _on_overlay_chosen(pact):
        if pact == null: return                  # left - altar stays usable, can come back
        is_used = true
        RunState.AddPact(pact)
        play a "used" animation / dim the altar, flash the player

  Interaction:
    - Add an "Interact" input action (E) in Project Settings -> Input Map. There's none yet.
    - "Walk away without choosing" = Leave button closes the overlay and nothing happens.
      Recommended: altar stays active until you pick something, so leaving isn't a trap.
      (Alternative design: leaving locks the altar. More tension, less friendly.)

  Rolling offers (seeded, so Ctrl+R shows the same offers in the same room):
    var rng = RandomNumberGenerator.new()
    rng.seed = hash([RunState.GetFloorSeed(), "altar", global_position])
    - filter pool: pact not in RunState.pacts, pact.min_floor <= RunState.floor_number
    - weighted pick without repeats (DungeonGenerator already has WeightedShuffle - move it
      somewhere shared like GlobalMethods, or copy the idea)
    - if fewer than 3 valid pacts remain, show what's left
    Roll in _ready, not when opened - otherwise reopening rerolls (free rerolls exploit).
    Use global_position (not a counter) in the hash so the result doesn't depend on room order.
    Make sure the room is already at its final position when _ready runs - if the generator
    adds the room before moving it, roll on first interact instead and cache it.

  Worldgen:
    - Data/Rooms (wherever your RoomData .tres live): AltarRoom.tres with
      room_scene = AltarRoom.tscn, room_type = SHRINE (or add ALTAR to the enum and rename),
      max_per_floor = 1, min_depth = 2-3, weight ~ RestRoom's.
    - Add it to the generator's room list. DungeonGenerator already sends non-COMBAT rooms to
      branch ends, nothing else to change there.
    - Minimap: give SHRINE rooms their own icon/color so players can find them.

  Room scene: any scene with connectors + Area2D footprint works (see CLAUDE.md). Duplicate
  RestRoom.tscn, replace Shrine with Altar (sprite + Area2D + prompt Label). Remember the
  Make Unique gotcha if you touch sprite_frames.

10. HUD + debug
===========================================================================================
  HUD: a row of small pact icons (top left under HP) built from RunState.pacts, refreshed on
  RunState.pact_added and in _ready (new floor). Tooltip/Tab view shows buff + curse text,

Build order (each step is playable/testable on its own)
===========================================================================================
  A. AltarPact + RunState.AddPact + Player.ApplyPact.
     Test: debug key adds the "vampiric / half HP" pact. Uses only existing systems
     (StatModifier + Effect), so this proves the pipeline end to end.
  B. VampiricSpellEffect (tinted shots, heal on hit).
  C. DamageInfo kill info (last_hit), enemy_killed(enemy, info), player_damaged signal.
  D. RunEffect base + RunState dispatch.
  E. Explosion scene (with telegraph), ExplodeOnKillEffect, the exploding-monsters pact.
  F. ChoiceOverlay (generic), tested via debug key.
  G. AltarRoom scene + script + Interact action + seeded offers + RoomData in the generator.
  H. HUD pact icons, enemy_modifiers, more pacts.

Pact ideas that fit these systems without new code once A-E exist:
  - "+40% spell damage, BUT enemies have +30% HP"         (modifiers + enemy_modifiers)
  - "+25% move speed, BUT taking damage costs 2x"          (needs a damage_taken_mult stat
                                                            read in Player.TakeDamage)
  - "Kills heal 2 HP, BUT you can't heal at rest shrines"  (RunEffect + a flag RestRoom checks)
  - "Every 5th kill fires a nova, BUT dash cooldown +50%"  (RunEffect with run_effect_state
                                                            counter + modifier on dash cooldown -
                                                            dash cooldown is on MobilityAbility,
                                                            not a stat yet)

Pitfalls to remember
--------------------
  - Shared resources: Effects/RunEffects in .tres are shared. Counters go in
    projectile.effect_state[self] or RunState.run_effect_state[self].
  - Ctrl+R: everything must come from RunState lists (cleared in Begin) + seeded rolls,
    so a restart is a clean, identical run.
  - Next floor (not implemented yet): Player is recreated -> ApplyLoadout re-applies all pacts.
    RunEffects must not keep node references across floors (OnAdded is called again).
  - Death during physics callbacks: spawn nodes with call_deferred.
  - Room cleared counting: enemies killed by an explosion still emit died -> EnemyRoom counts
    them correctly. An explosion after the last enemy dies can still hurt the player; fine.
